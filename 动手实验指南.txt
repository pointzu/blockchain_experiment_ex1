四、修正金额转换，并准备广播接口

1. utils.py 中原 create_txout 使用 amount*COIN，可能产生浮点数，不适合交易输出的整数 satoshi。文件顶部加：

from decimal import Decimal

把 create_txout 替换为：

def create_txout(amount, scriptPubKey):
    satoshis = Decimal(str(amount)) * COIN
    if satoshis != satoshis.to_integral_value():
        raise ValueError('金额不能包含不足 1 satoshi 的部分')
    if satoshis <= 0:
        raise ValueError('输出金额必须大于 0')
    return CMutableTxOut(int(satoshis), CScript(scriptPubKey))

2. 课程原 broadcast_transaction 使用 BlockCypher。它目前对你的领取交易返回 404；助教关于更换浏览器的提示仅涉及查询，并没有明确要求更换广播接口。
为避开旧接口无法索引输入的潜在问题，本指南建议把 utils.py 的 broadcast_transaction 改为官方 Esplora 接口：

def broadcast_transaction(tx):
    raw_transaction = b2x(tx.serialize())
    return requests.post(
        'https://blockstream.info/testnet/api/tx',
        data=raw_transaction,
        headers={'Content-Type': 'text/plain'},
        timeout=30,
    )

这项改动属于本指南的兼容性建议。报告中如实写明原因。Esplora 要求请求正文直接是十六进制交易，不是 {"tx": ...} JSON。
官方文档：https://github.com/Blockstream/esplora/blob/master/API.md
成功响应通常为 HTTP 200，正文为 64 位交易哈希，和 BlockCypher 的 JSON 响应格式不同。
修改接口不会立即广播，只有运行分币或发币脚本时才提交交易。

六、自己补全 ex1.py 的 P2PKH

1. 锁定脚本需要“复制公钥、计算哈希、匹配指定公钥哈希、验证签名”。把函数改为：

def P2PKH_scriptPubKey(address):
    return [
        OP_DUP,
        OP_HASH160,
        bytes(address),
        OP_EQUALVERIFY,
        OP_CHECKSIG,
    ]

此处参数必须是 P2PKH 地址。bytes(address) 是解码后 20 字节的公钥哈希，不是地址字符串的 UTF-8 编码。
学长从标准脚本的 [3:-2] 截取哈希也能用于标准 P2PKH，但直接取地址 payload 更清楚。
不要用 return address.to_scriptPubKey() 代替这一 TODO：课程要求在操作码级别显式编写脚本。

2. 解锁脚本把签名和公钥依次放入栈。改为：

def P2PKH_scriptSig(txin, txout, txin_scriptPubKey):
    signature = create_OP_CHECKSIG_signature(
        txin, txout, txin_scriptPubKey, my_private_key)
    return [signature, my_public_key]

create_OP_CHECKSIG_signature 已计算交易签名摘要，签名后还附加 SIGHASH_ALL 标识，不需要你重复签名。
VerifyScript 会在广播前检查本地脚本，但不会替你确认输入仍未花费、真实前序输出金额或链上确认状态。

八、常见错误

WinError 193 / NoneType：先在同一个 PowerShell 执行第三节的 DLL 路径命令，再验证导入。
Base58 校验失败：检查私钥是否仍为 X、复制是否完整、有没有空格。无需展示私钥。
config 地址不一致：使用了另一个私钥；先找回领取地址对应的原私钥。
整数类型或浮点金额报错：确认 utils.py 使用 Decimal 转整数，金额变量也使用 Decimal。
missing inputs / input not found：检查 txid、vout、网络和未花费状态；发币时应引用分币哈希。
already spent / txn-mempool-conflict：先检查链上记录，避免重复花费。
脚本校验失败：核对使用的私钥、公钥、输入地址以及两个 TODO 的顺序。
手续费不足：查询当前费率，重新计算输出金额；先检查原交易是否已入池。
查询不到：确认路径含 /testnet/，不要去主网、testnet4 或 signet 查询；BlockCypher 查不到不等于没有到账。
